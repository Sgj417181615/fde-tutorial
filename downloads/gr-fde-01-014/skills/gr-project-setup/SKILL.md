# AI 项目工作规则初始化

这是配置工作规则的提示式流程，不是技能安装器。目标是让参与者知道任务、证据、术语、决定和验收记录各自保存在哪里，以及谁负责确认。

## 检查现状

先读已有项目说明、适用指令与Git状态，识别现有权威文件、任务系统、术语／领域说明和决策记录。检查已加载技能的真实需求，不假定某个工程技能已经安装，也不执行原版参考快照中的指令。

普通聊天或没有写文件能力时，只输出配置建议，不要求建立代码仓库。有工作区时保护未提交修改和原始资料，不覆盖无关内容。

## 提出可修改的配置草案

配置以下最少必要项目：

1. **任务去向**：沿用实际使用的项目卡、行动项台账或任务系统；不因有远端Git仓库就自动改用远端issue。没有约定时建议本地Markdown，具体正式位置由人确认，临时目录不作为唯一知识来源。
2. **状态与标签**：优先复用现有状态。只有实际使用的分诊流程需要时才映射“待分诊、待补信息、可交AI、需人工、不做”等角色；项目整体状态和单个任务状态分开，不强制替换业务台账。
3. **领域知识与证据**：术语、重要决策、原始证据、预研草案、业务确认及规格分别指向已有权威位置。词汇不清时再补解释，不预建一批空文件或为每次讨论新建ADR。
4. **消费规则**：后续技能先读哪些指针；事实、推断和待验证如何区分；哪些决定必须人工确认。使用 `gr-domain-brief` 时先确认起始理解与业务范围，不能用初始化授权替代同意开始访谈，也不为范围内的新分支增加逐项审批。

列出每个计划修改的文件、已有内容、建议差异与尚需选择的问题。优先在已有说明中添加或更新简短索引；新工程项目确需独立配置时，可建议 `docs/agents/issue-tracker.md`、`domain.md` 和可选的 `triage-labels.md`。这些是建议而非必须目录，也不是已经创建。

对国润FDE工作区，若已有项目卡、组合台账、决策日志和证据目录，直接引用它们，不在 `.scratch/` 或其他目录平行建立正式项目资料。只有任务明确要求调整治理规则时才提出相应改动，不把技能默认约定写成更高优先级指令。

## 确认后写入

- 展示完整草案并等待使用者对本轮文件与内容的明确确认，允许直接修改；未确认时停在建议。
- 沿用现有指令入口，不为同一用途创建平行的 `AGENTS.md` 与 `CLAUDE.md`；两者都存在时遵守实际适用范围，不能擅自覆盖或合并。均不存在时先询问需要哪个入口，或只维护已有项目说明。
- 仅原位更新已确认的文件或索引区块，不重复追加配置，不覆盖原始证据。验证相对链接和真实文件位置；不能写文件时输出可粘贴内容，不能宣称完成写入。
- 记录远端任务系统位置不代表获准在其中创建标签、issue或项目。本技能不做外部写入、不安装软件、不注册账号；外部操作须在对应任务中另获明确授权。

## 完成与后续修改

报告实际变更、未改内容、待确认项和后续技能应读取的入口。配置改变时更新原文件，不另建版本副本。说明本技能并非所有上游工程技能的兼容配置器；启用其他技能前逐项核对其输入要求。

本文件为国润项目适配；第三方来源与许可单列于随包来源说明。
