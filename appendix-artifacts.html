产物链与档案

42 个 artifact 的生产者、消费者、阶段门，以及 7/12/42 三档档案。

本页要回答这份产物从哪来、交给谁、不过关会卡住什么？

读完你能

  • 查出一个 artifact 的上游与下游；
  • 区分现场包、最小档案与完整档案；
  • 判断当前项目缺哪份关键产物。

前置

无前置，从本页开始。

“这份产物从哪来？”不是问文件放在哪个文件夹，而是问：谁在什么阶段写它，写完交给谁，哪道门会检查。42 个 artifact 按 00–06 七个阶段组织，G0–G6 七道阶段门把它们串成一条链。

这一页不逐字段讲模板，而是讲链的方向：谁写、给谁、过哪道门。需要空白文件和填写样例，去模板库。

三档档案：7 / 12 / 42

档 份数 什么时候用 它保证什么
90 分钟现场包 7 明天就要去客户现场 能问、能记、能授权，并能检查五道门
最小可交付档案 12 想完整跑一轮验证 从项目章程到复盘有一条可追溯的证据链
完整档案 42 要交接、审计或复用 七个阶段的所有产物齐全，下一任能独立接手

现场包和最小档案不是简单相加。两边都保留的 6 份共同底座是 A00-01、A00-04、A01-02、A02-01、A02-04、A05-01；现场包另有 A01-03，最小档案则补入 A00-02、A03-01、A03-05、A04-02、A05-06、A06-01。最小档案没有 A01-03，不是遗漏，而是它选择用 As-is 和 one-pager 来承接现场观察。

7/12/42 是三种起步规模，不是三套验收标准。阶段门仍按阶段检查关键证据；最小档案能让你跑完一轮，交接档案才要求所有节点齐全。

一条链怎么读

每份产物都有四个坐标，缺一个就不成链：

  • 谁写（生产者）：在哪一页被写出来。表里给的是页面简称，比如 主线·切片 就是《把“系统”切成可验证的决策》那一页；点开就是原页。多个入口不表示可以没人负责。
  • 谁读（消费者）：下一阶段哪一页必须读它、拿它做决定。消费者为空，通常说明这份产物还没有进入真实决策。
  • 阶段门：在哪道门被检查。G0–G6 是检查门，不等于文件所在目录的阶段（例如 A00-05 放在 00 目录，检查在 G1），也不等于只在那一天才看。
  • 档位：它是否属于 7 份现场包或 12 份最小档案。没有标记的产物仍然属于完整档案。

举个例子。A03-05 use-case one-pager 的“谁写”是 主线·一页纸：这一页负责把它写出来；它的“谁读”是 主线·FR、主线·方案、主线·五道门：这三页要读它，并在它基础上继续写 FR、设计方案、判断能不能启动。查上游，从你手上的文件找“谁写”；查下游，从“谁读”看它会被谁使用。一个 artifact 如果没有任何下游，通常不是“不重要”，而是链断了。

页面里的“本页要写出的产物”会自动列出同一组关系。你不用背编号，只要知道当前页面写什么、下一页面读什么。

阶段门卡在哪里

先分清三个容易混的说法：阶段门 G0–G6 管“这一阶段的产物齐不齐、能不能进下一阶段”；五道门是开始五天验证前的准备检查，落在 A05-01 上，不等于 G0–G6；质量门是单页或单份产物的通过标准，比如 A00-05 模板末尾的自检清单。三者都叫“门”，检查对象不同。

七道阶段门各问一句，你就能判断手上的产物够不够：

  • G0 项目章程门：为什么做、为谁做、不做什么、数据能不能碰？
  • G1 调研准备门：到了现场，是否知道问谁、问什么、记什么、拿什么基线？
  • G2 现场记录门：三天后回看，每条结论还能不能追到原文或观察？
  • G3 现状与切片门：选中的切片是否窄到五天内能验证，又真实到值得做？
  • G4 方案设计门：方案是否支撑那个决策，而不是一堆好看的页面？
  • G5 验证执行门：五天结束要展示的决策，今天是否已经能被真实用户完成？
  • G6 复盘与回流门：这一轮留下了什么可复用资产，下一轮凭什么会更好？

不过门时，正确动作是回上一阶段补证据，不是用“先做平台”或“先做界面”绕过去。门不是审批仪式；它保护的是下一阶段产物的输入质量。

README 与档案目录

项目档案按七个阶段分目录，每一份产物放进对应目录。文件名规则是 <阶段号>-<序号>_<名称>.md，例如 02-04_证据台账.md；不带 A 前缀，A02-04 是链上的 ID，不是文件名：

FDE项目档案/ ├── 00_项目章程/ ├── 01_调研准备/ ├── 02_现场记录/ ├── 03_现状与切片/ ├── 04_方案设计/ ├── 05_五天验证/ ├── 06_复盘与回流/ └── README.md

模板留在 templates/，不要放进档案目录；档案里放的是你已经填过的产物。复制模板时改的是内容，不是编号和文件名，否则下一任读者无法把文件和链上的节点对上。

不想手工建目录，可以直接下载按这个结构摆好的档案包。三个包内容不同，按你明天要做的事选：

7 份90 分钟现场包明天就要去客户现场时带的 7 份空白模板，按档案目录摆好。fde-field-pack.zip12 份最小可交付档案从章程到复盘的最小证据链，适合完整跑一轮验证。fde-minimal-dossier.zip42 份完整档案骨架42 份空白模板按 00–06 目录摆好，用于交接、审计或复用。fde-dossier-skeleton.zip

全部为离线 zip：解压即用，不联网、不需要安装。模板是 Markdown 文件，用任意文本编辑器或 Obsidian 打开。工具包下载在 Day1 总览。

根目录的 README.md 只写三行，作用是导航，不是项目总结：

项目名：<一句话>
当前阶段：G2 现场记录
下一次要更新：A02-04 证据台账（负责人，日期）

每次过门更新一次即可。不要把 42 个文件名全抄进 README；真正的清单在上面的表里。

判断当前缺哪份

用四步查缺口：

  1. 在档案 README 找到当前阶段，确认上一道门是否真的过了。
  2. 在上面的阶段表里找到下一道门对应的阶段。
  3. 逐份打开：文件存在不等于产物成立。关键字段为空、结论没有证据 ID、没有负责人，都算缺。
  4. 先补最小集或现场包里标“是”的产物；其余按门的检查项补，不要一次铺开 42 份。

停一下：打开你的档案目录，任选一份产物，回答三件事：谁写它、谁读它、哪道门检查它。三问答不齐，这份文件可能只是留档，还没有进入产物链。

本章带走

  • 42 个 artifact 是一条有方向的链：生产者写、消费者用、阶段门检查。
  • 7 份现场包、12 份最小档案、42 份完整档案是三种起步规模，不是三套标准。
  • README 只写项目名、当前阶段、下一次要更新的 artifact；空文件不算产物。
