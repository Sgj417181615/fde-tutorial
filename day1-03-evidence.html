确认记录与证据状态

四类访谈状态、五级来源权威性、双轴标注和确认记录，防止把“说过”当“事实”。

本页要回答业务方说了一句话，它在证据链里到底算第几等？

读完你能

  • 给每条记录标四类访谈状态；
  • 同时标来源权威性并解释双轴；
  • 写出一份可签字的确认记录。

前置

先读：分轮访谈

何时用
每次访谈或观察结束后，以及 D1 收口、确认记录签字之前
前置
A01-02 提纲、A02-01 观察记录、A02-02 逐字稿、A02-03 术语表
主要产出
A02-04 证据台账、A02-05 待确认清单、A02-06 D1 确认记录
阶段门与耗时
G2 现场记录门；阅读约 16 分钟，现场执行约 50 分钟

D1 收口前，你在白板上写下“额度不能跨月”。有人问谁说的，你只找到自己发的“应该是吧”。这不是证据，是工作假设；三天后它可能被写成“业务规则”。证据状态要回答：验证到什么程度？凭什么信？能用到哪里？

何时用

该用：访谈或观察当天；把“业务方说”写进一页纸、规则库或 FR 前；D1 结束请业务方确认关键结论。

不该用：无许可时先补数据权限与录音许可；公开资料走来源登记；会议纪要不能替代证据台账。

前置与输入

输入 从里面取什么 缺了怎么办
A01-02 分轮访谈提纲 问题编号、期望证据、追问 先补提纲，否则不知道哪轮该确认什么
A02-01 现场观察记录 时间、角色、动作、卡点 先复原现场，不能凭印象补
A02-02 逐字稿 原话、语气、说话人 没有录音就标“现场笔记，未录音”
A02-03 术语与说话人表 业务词含义、说话人身份 先对齐术语，避免听错概念

A02-03 决定“谁有资格确认”。同一条规则，排班员和规则所有者的说法，分量不同。

四类访谈状态

访谈证据状态只有四类。一条证据只能选一类，不能同时写“原文 + 已确认”。

状态 判定标准 记录要求
原文/观察 你能回到具体时间、说话人或动作，且有当时记录（录音、逐字稿或现场笔记） 保留原话和场景，不润色、不概括
业务确认 对方听完你的复述后明确点头、纠正或书面回复 写清谁确认、何时、原话是什么
工作假设 这是你从多条线索推出来的，对方没有明确确认 写成“我们假设……”，并写验证方式
待验证 有一个具体说法，但来源、版本或口径尚未核对 进入 A02-05，写负责人和截止日期

五条边界最容易错：

  1. “他没反对”不是业务确认。 只有明确点头、说“对”、签字或书面回复才算。
  2. “业务方原话”不是官方规则。 原话说明你记录准确，不说明这句话是正式制度。
  3. 工作假设是“你推出来的解释”，待验证是“有一个说法，但还没核实”。
  4. 一段话里有三个判断，就拆成三条 E-xx。 例如“额度不能超，超了要写说明，模板在群里”涉及规则、动作、材料三件事。
  5. 事后凭回忆补的记录不是原文/观察。 只有笔记没有录音时，在来源里写“现场笔记，未录音”，状态最高记到“业务确认”；回忆出来的概括只能记“工作假设”。

来源权威性五级

来源权威性回答另一个问题：凭什么信这句话？

级别 判断标准 典型来源 能支撑什么
官方 有正式发布主体，原文可查，对项目有约束力 法规、正式制度、合同、官方文档 硬约束、正式口径；引用要能指到原文
第三方 外部作者或机构的研究、方法、基准 行业报告、公开方法论、外部案例 参考、对照、假设来源；不能当客户规则
实践 客户现场真实做法或角色原话 观察、访谈、排班本、现有表格 现状重建、痛点判断；不能自动当正式制度
推断 团队根据线索做出的解释 你的归纳、对比、常识判断 只能写成工作假设
待确认 来源不明、版本冲突、尚未核对 截图、转述、过期表格、传闻 只能进入待确认清单

关键句：访谈状态回答“验证到什么程度”，权威性回答“凭什么信”。 一条“业务方原话”可以是“原文/观察 × 实践”，仍然不是“官方”。

停一下：周主任在访谈里说“总额度不能超”，这是“官方”吗？

不是。它是“业务确认 × 实践”：你确认了周主任的态度，但手里没有正式制度原文。要写成硬约束，最好再拿到制度或书面规则。

双轴判定卡

把两个轴交叉，才能决定一条证据能不能进入结论。这张表可以直接打印。

双轴判定卡 状态 × 权威性
访谈状态 \ 权威性 官方 第三方 实践 推断 待确认
原文/观察 A B B C D
业务确认 A B B C D
工作假设 C C C C D
待验证 D D D D D

读法：

  • A：可作为正式依据或硬约束，但仍要写出原文位置与确认人；
  • B：可作为方案依据，引用时必须标来源与证据 ID；
  • C：只能写成工作假设，不能写成“业务方认为”；
  • D：不能支撑结论，只能进入 A02-05，等验证后再升级。

“工作假设 × 官方”仍然是 C。你引用了一份官方文件，不代表你的推断自动变成官方结论。

用 CB-14【示例】读一遍：E-01 是“原文/观察 × 实践”＝B，可以描述现状；E-04 是“业务确认 × 实践”＝B，可以写审批规则的工作依据；E-05 是“工作假设 × 推断”＝C，只能写“我们假设额度不能跨月”；E-06 是“待验证 × 待确认”＝D，不能写“王芳只能上 9 天”，只能开问题单。

操作步骤

  1. 切分原句（5 分钟）：一句只留一个可判断的主张；包含多个主张的，拆成多条 E-xx。
  2. 判定状态（10 分钟）：问三件事：这是原话/动作，还是我的解释？对方明确确认了吗？有没有具体说法尚未核实？
  3. 标权威性（5 分钟）：看来源，不看职位。正式制度是官方，现场做法是实践，你的解释是推断，来源不明是待确认。
  4. 做双轴校验（5 分钟）：查判定卡。C 改成“我们假设……”；D 搬到 A02-05，不留在结论区。
  5. 建待确认清单（10 分钟）：每条 D 或未决的 C，写影响、当前假设、验证方式、负责人、截止日期、状态。
  6. 写确认记录（10 分钟）：只记明确确认或纠正的内容。复述结论，请对方用自己的话再说一遍；点头后记录原话和仍未确认项。

最后留 5 分钟过 G2：抽查三条将进入方案的结论，看能否回到 E-xx、状态和权威性。

三份产出与字段

三份文件都在 02_现场记录/ 下，字段不要自创。

A02-04 证据台账

九列，一行一条证据。可直接抄这张空表：

A02-04 证据台账 九列骨架
证据ID 原文或观察 来源 访谈状态 权威性 影响决策 待确认项 负责人 截止日期
E-01
E-02

“影响决策”写具体判断，如“额度校验规则”，不要写“有用”。“原文或观察”栏不要出现“我觉得”。

A02-05 待确认与问题清单

七列：问题、影响、当前假设、验证方式、负责人、截止日期、状态。放双轴为 D 的条目、未确认的关键 C、版本或口径冲突，以及会影响 D1 结论或 D2 计划的问题。

一条问题只写一件事。“额度规则不清楚”太宽；“12 人天是否含夜班”可以直接验证。

A02-06 D1 确认记录

六字段，缺一不可：

A02-06 D1 确认记录 可打印签字
确认时间：
参与人：
确认内容：
业务方原话：
仍未确认项：
下一步：

三条规则：原话不转述；确认人要有权确认这条规则；仍未确认项不能留空。 对方只说“差不多”，写进“仍未确认项”。

排班案例的一条填法【示例】：

字段 填写
确认时间 D1 下午【示例】
参与人 周主任、FDE
确认内容 总额度不得超过；超出时要写说明
业务方原话 “总额度不能超，超了要写说明。”
仍未确认项 说明模板是否存在；额度能否跨月（E-05）
下一步 周主任提供说明模板；FDE 向孙老师确认规则，截止 <日期>

打印后由参与人在“参与人”栏手签，附在 A02-04 后面。

排班案例：从原话到台账与确认

案例 CB-14 里有六条证据（数字均为【示例】）。不要只看“写了什么”，要看“每条能怎么用”：

  • E-01、E-02 都指向“三个 Excel 并存”，都是 B，可以共同支撑“版本不统一”；
  • E-03“妇科至少 12 个”是赵岚原话，B；但“12 是否含夜班”仍是待确认项；
  • E-04 是周主任的业务确认，B，可以写审批规则的工作依据，但仍不是官方制度；
  • E-05 是工作假设 C，只能写“我们假设额度不能跨月”；E-06 是 D，不能证明 C1 已成立。

双轴的作用，是逼你在写结论前先决定：这句话有没有资格进入结论。

动手 15 分钟：从最近一次访谈里抽三条“业务方说”，做双轴标注。

  1. 每条拆成一个可判断的主张，编号 E-01 到 E-03；
  2. 标状态与权威性，查表得到 A/B/C/D；
  3. 把 C 改写成“我们假设……”；把 D 搬到待确认清单；
  4. 选一条最重要的 B，写一行 A02-06 确认记录，补上仍未确认项。

自检：① 有没有把“没反对”写成“业务确认”；② 有没有 D 还留在结论里；③ 确认记录写的是原话还是概括。

常见失败

现象 原因 处理
台账每条都是“业务确认” 把“没反对”当确认 只有明确点头、纠正或书面回复才算；否则降为工作假设
原话漂亮，但找不到说话人 只抄了结论 回逐字稿补时间、角色；补不了就降级
一条证据支撑五个结论 证据被过度解释 一条证据只支撑它直接说明的判断
双轴只标状态，没标权威性 把“谁说的”当成“凭什么信” 两轴都标；原话通常是实践，不是官方
待确认清单没有负责人 把清单当问题池 每条必须有人名和日期；没有就升级为阻塞项
确认记录写成会议纪要 按时间记，不按确认点记 只留六字段；一条确认一张记录

三问自测

1. 业务方说“应该不能跨月”，可以标“业务确认”吗？ 不可以。这是推测语气，且没有明确确认。应标“工作假设”；如果有具体说法待核实，也可以标“待验证”，并进入待确认清单。
2. “原文/观察 × 实践”能直接当硬约束吗？ 不能。它适合描述现状和痛点，不等于正式规则。硬约束需要官方来源，或规则所有者明确确认并留下记录。
3. 为什么“工作假设 × 官方”仍是 C？ 因为访谈状态描述的是你的判断有没有被确认，不是来源本身有多权威。你引用官方材料做推断，推断仍然是推断。

自检清单

  • [ ] 每条 E-xx 只有一个状态和一个权威性；
  • [ ] 原话与解释分开，原话没有被润色成结论；
  • [ ] 所有 C 都写成“我们假设……”，没有伪装成业务确认；
  • [ ] 所有 D 都进入 A02-05，有验证方式、负责人和截止日期；
  • [ ] 每条关键结论都能回到 E-xx 和原始来源；
  • [ ] A02-06 六字段齐全，原话准确，参与人有权确认。

本章带走

  1. 四类状态回答“验证到什么程度”，五级权威性回答“凭什么信”；两个轴必须同时标。
  2. “业务方原话”不等于官方，“没反对”不等于确认；工作假设和待验证都要有下一步。
  3. 双轴为 D 的条目不能进结论，只能进待确认清单；确认记录只写明确确认的内容和原话。

本页术语

证据台账 Evidence Ledger

逐条记录原文/观察、来源、访谈状态、权威性、影响决策和待确认项的账本。

首次解释

确认记录 Confirmation Record

记录谁在什么时候确认了什么、原话是什么、还有什么没确认的简短记录。

访谈证据状态 Interview Evidence State

四类状态：原文/观察、业务确认、工作假设、待验证；它回答“这条信息被验证到什么程度”。
