从证据到模型

决策清单、四类规则、As-is 与切片打分：把访谈材料加工成可设计的东西。

本页要回答手上有一堆访谈记录，下一步怎样加工成模型而不是直接建表？

读完你能

  • 从证据中抽出决策与动作；
  • 把规则分成配置、硬约束、软偏好、优化目标；
  • 用打分卡重新比较候选切片。

前置

先读：记录：把现场变成证据

何时用
G2 记录门通过后、写 one-pager 或画方案之前
前置
证据台账完整，每条结论都能回到证据 ID
输入
A02-01～05：观察、逐字稿、术语表、证据台账、待确认清单
输出
A03-01 决策流、A03-02 用户-决策-动作清单、A03-03 切片打分、A03-04 规则库
阶段门与耗时
G3 现状与切片门；约 3 小时，可拆两次

访谈记录铺满桌面，你打开建表工具，准备先建人员表、班型表、额度表。字段很顺，半小时画完。但画到一半会发现：三张表没回答“陈静在哪一步、凭什么、把谁分到哪个亚专科”。表能存数，不能替你决定做哪个决策。

从证据到模型，先加工判断，不是字段。本页做四件事：圈决策、还原 As-is、分层规则、比较切片。

何时用

该用：

  • G2 通过，准备把材料收窄成一次交付；
  • 你开始按“数据表”或“页面”想方案，而不是按“谁做什么决定”想；
  • 候选切片不止一个，需要把选择理由摆上桌。

不该用：

  • 台账里还有无法复核的记录。先回 记录：把现场变成证据 补齐；
  • 客户已给出签字范围且不许改。仍要做规则库；
  • 只有查看和导出、没有决策的场景，不要硬造。

停一下：从台账抽三条证据，它们共同指向哪一个“必须选一个”的决定？如果指向三个不同决定，你还在收集阶段，不是加工阶段。

前置

前置 判断标准 没做到会怎样
G2 已通过 抽查三条结论都能回到证据 ID 模型建在无法复核的概括上
A02-04 台账 每条有状态、权威性、影响决策 分不清事实、确认和假设
A02-05 待确认 每条有负责人和截止日期 未决项在评审时变成阻塞
业务专家 30 分钟 能确认硬约束的例外和确认人 规则只能停在“待确认”

规则必须有人说“这条不能破，破例找谁”，否则 A03-04 只是草稿。

输入

输入 取什么 用在哪
A02-01 观察记录 时间、角色、动作、卡点 还原非正式步骤
A02-02 逐字稿 决策动词、条件句、例外句 圈决策、抽规则
A02-03 术语表 业务词与数据字段的对应 统一用词
A02-04 台账 证据 ID、状态、权威性 给模型挂证据
A02-05 待确认 未决问题、当前假设 标出假设边界

不要重新访谈。加工是在已有证据上归类，不是再收集。发现缺口记进 A02-05，不要用想象补。

六个加工步骤

第 1 步：圈决策句，不圈名词（30 分钟）

通读逐字稿和台账，只标“在几个选项里选一个”的句子。三问判断：

  1. 有候选：是“分给 A 还是 B”，不是“需要人员信息”；
  2. 有后果：选错会影响额度、班次或审批；
  3. 有人承担：有明确决策人和时点。

案例 CB-01 里，“额度不够时先借下月”不是决策，是例外规则；“本月每个亚专科用多少、分给谁”才是。决策 要求选择并承担后果，查看、导出都不算。

把留下的决策写进 A03-02：角色、场景、决策、时点、输入、动作、系统、频率、证据 ID。一行一个决策；出现“并且”连接两个不相干的决定，就拆行。

第 2 步：把 As-is 画成决策流，不画部门流程（45 分钟）

用 案例 CB-01 的五步做骨架：收额度、收需求、凭记忆核对、电话协调、审批录入。每步填九字段：步骤、角色、触发、输入、判断规则、输出、耗时、痛点、证据 ID。

三个判断标准：

  • 每步一个动词、一个输出物。 “核对”的输出是“每人可用天数估计”，不是“完成核对”；
  • 保留没写进制度的步骤。 纸上草表、按“上次谁让过步”平衡、微信临时改，都是真实判断，往往正是切入点；
  • 没证据 ID 的步骤标“待验证”，不要删。 删掉会让流程比现实干净，设计就会漏例外。

官方把 use case 看作有生命周期的交付单元，先定义问题与价值，再建设 [S01]。As-is 是定义问题的底图，不是流程美化稿。【实践】[S17]

第 3 步：把规则分四层（45 分钟）

四类规则分层 把“应该、必须、尽量”分成四层。分层决定系统该阻止、提示，还是只用来比较方案。

层级 判断问题 违反后 排班案例
配置数据 是可维护的名单或枚举吗？ 配置错了流程还能走 R-01 班型、R-02 亚专科
硬约束 违反后方案直接无效吗？ 必须阻止保存或提交 R-03 一人一班、R-05 不超天数
软偏好 违反后只是变差吗？ 提示、不阻断 R-06 连续班
优化目标 是在可行方案里比好坏吗？ 只影响排序 R-07 缺口最小、R-08 均衡

每条再补适用对象、例外、冲突、确认人、证据 ID。按顺序问：

  1. 违反它，方案还成立吗？不能，是硬约束；
  2. 谁有权破例？有例外路径的硬约束，必须写批准人；
  3. 系统该阻止还是提示？阻止对应硬约束，提示对应软偏好；
  4. 它在淘汰方案，还是比较方案？比较的是优化目标。

案例 CB-15 的关键纪律必须抄：R-07、R-08 是优化目标，不能写成硬约束。否则系统会为“缺口最小”排出数学最优、现实没人执行的班。R-05 是硬约束，C1 必须被拦住，不能只弹“建议调整”。

第 4 步：用最短行动闭环检查候选（30 分钟）

最短行动闭环 是：让真实用户，用真实数据，完成一次有价值的动作，并产生可观察反馈。写成模具：

【角色】在【场景】，用【真实输入】，完成【一个决策动作】，看到【可观察反馈】。

案例 CB-02 的 S1 可填成：陈静在月度额度分配场景，用需求、额度和可用天数，决定每个亚专科用多少、分给谁，并看到已分配、剩余、缺口与冲突。

四个空有一个填不出，先别打分：角色填不出是还在写“业务部门”；输入填不出是数据没着落；动作填不出是功能不是切片；反馈填不出是没人能判断对错。

第 5 步：四维打分，先过硬门槛（30 分钟）

切片打分卡 用价值、可行性、证据强度、风险四项，每项 1–3 分。先给每档写锚点，再打分；否则同一个人上午下午能打出两个结果：

维度 3 分 2 分 1 分
价值 直接改变每月关键决策 减少返工或等待，但不改变决定 只让查看更方便
可行性 五天内技术和数据有把握 有一项依赖需在 D-1 前补齐 数据拿不到、权限没着落
证据强度 有观察、原话和数据 有原话，但只有单一来源 只有“应该有需求”
风险 出错影响临床、依赖多系统 出错可回退，依赖一个系统 出错代价低、依赖少

风险分越高，表示越危险，方向与其他三项相反：总分只把价值、可行性、证据强度相加，风险单独看，不加进总分。先过硬门槛：只含一个最终决策；五天内能端到端跑通。硬门槛不过，分值再漂亮也不选。

案例 CB-02 里 S4 可行性高、证据强、风险低，但最终决策是“无”，所以不做；S2 价值不低，却依赖 S1 的结果，只能第二轮。打分不是算总分，是把“为什么不选它”写成可检查的理由。

第 6 步：交叉核对，过 G3（30 分钟）

四份产物必须对上：

  1. A03-02 的每个决策，能在 A03-01 找到发生步骤；
  2. A03-03 选中切片只含一个最终决策，输入有来源；
  3. A03-04 硬约束有确认人，优化目标没混层；
  4. A02-05 的未决项在规则库或打分表有落点。

四项都过，才进 one-pager。对不上就改模型，不要靠汇报时口头解释。

输出

输出 路径 最小内容 下游
A03-01 As-is 决策流 03_现状与切片/03-01_As-is决策流.md 九字段齐全，含非正式步骤与证据 ID work-05、main-04
A03-02 用户-决策-动作清单 03_现状与切片/03-02_用户-决策-动作清单.md 一行一个决策，有角色、时点、动作 main-04、main-05
A03-03 候选切片与打分 03_现状与切片/03-03_候选切片与打分.md 四维分值、硬门槛结论、选择理由 main-04、main-07
A03-04 规则库（四层） 03_现状与切片/03-04_规则库.md 层级、例外、冲突、确认人、证据 ID main-05、work-05

阶段门

G3 通过：一个切片、一个最终决策、一条完整操作路径；As-is 保留真实步骤；四层规则分开；每条硬约束有确认人。

有条件通过：只缺一条证据或一个数据口径，已标假设，且不在演示主路径上。补齐期限和负责人后放行。

不通过：找不到最终决策；优化目标写成硬约束；切片依赖未建成的上游；硬约束没有确认人。回对应步骤重做。

模板

先抄 A03-04 骨架。完整空白模板在 templates/blank/03-04_规则库.md，其余三份同名。

A03-04 规则库（四层） 可直接复制
规则ID 规则原文 层级 适用对象 例外 冲突 确认人 证据ID
R-01 配置数据 / 硬约束 / 软偏好 / 优化目标
R-02

填写说明：规则原文保留业务方说法，不改写成代码条件；层级四选一；例外写谁批、什么条件下批；冲突写谁优先；没有确认人的规则不能进实现。

排班案例

案例 CB-01 的五步可直接落成 A03-01 前五行。以第 3 步为例：

步骤 角色 判断规则 输出 痛点 证据ID
凭记忆核对 陈静 翻排班本、年假表、门诊表和会诊聊天记录 每人可用天数估计 依据不可复核 E-xx

“凭记忆核对”不是坏习惯，而是当前真实的判断步骤。方案要替代的是输入分散和结果不可追溯，不是做一个“人员主数据页”。

案例 CB-15 展示规则库成品：R-01、R-02 是配置；R-03 至 R-05 是硬约束；R-06 是软偏好；R-07、R-08 是优化目标。最易写错的是后两条——它们互相冲突，只能比较方案，不能阻止保存。

案例 CB-02 展示打分后的选择：S1 选中，S2 第二轮，S3 暂缓，S4 不做。S1 站得住，不是因为分最高，而是它只含一个每月真实发生、结果能写回的决策。

常见失败

现象 原因 处理
先画三张数据表，再回头找决策 把建模当建库 停表，先写 A03-02；字段服务决策或规则
As-is 只有制度流程 只记“应该怎样” 补纸上草表、微信协调，并标证据
优化目标写成硬约束 把“希望更好”当“必须满足” 四问重判；优化目标只影响排序
每条规则都没有确认人 自己推规则 找业务专家逐条确认，否则标“待确认”
一个切片塞两个最终决策 按部门或功能切 拆成两个切片，各写闭环
打分口径不一，风险方向反了 边讨论边改标准 先定 3/2/1 锚点；风险高记高分，且不并进总分

动手 20 分钟：从台账抽 8 条证据做最小加工。

  1. 圈出唯一最终决策，写成 A03-02 一行；
  2. 为它写一条 As-is 步骤，填角色、规则、输出、证据 ID；
  3. 抽两条规则判层，写出确认人；
  4. 用模具写闭环，四个空填满。

自检：决策句有候选和后果；步骤有输出物；两条规则不同层；闭环有可观察反馈。

三问自测

1. 为什么“查看额度全景”不算决策？ 它没有候选、后果和选择，看完可以不改变任何动作。可以作为辅助功能，但不能成为切片的最终决策。
2. 优化目标为什么不能写成硬约束？ 硬约束淘汰无效方案，优化目标在有效方案间排序。把“缺口最小”写成硬约束，系统会拒绝所有有缺口的方案，而不是帮人比较哪个缺口可接受。
3. 为什么先写最短行动闭环，再打分？ 闭环句逼你填清角色、真实输入、决策动作和反馈。四个空填不满，说明切片太大或没有决策；这时打分只会把错误选项算得更精致。

自检清单

  • [ ] A03-02 一行一个决策，含角色、时点、输入、动作；
  • [ ] A03-01 每步有动词、输出物和证据 ID；
  • [ ] As-is 保留纸上草表、口头协调等非正式步骤；
  • [ ] 四层规则分开，优化目标没有混进硬约束；
  • [ ] 每条硬约束有例外路径和确认人；
  • [ ] 候选切片能填满闭环四空，打分口径一致；
  • [ ] 选中切片只含一个最终决策，五天内能跑通。

本章带走

  1. 从证据到模型，先加工决策，再加工字段。
  2. As-is 保留真实的非正式步骤；规则分清配置、硬约束、软偏好、优化目标。
  3. 切片先用最短行动闭环验一遍，再按价值、可行性、证据强度、风险打分。

本页术语

决策 Decision

在几个候选方案里选一个并承担后果；查看、了解、导出都不算决策。

首次解释

四类规则分层 Four Rule Layers

配置数据、硬约束、软偏好、优化目标四层；优化目标绝不能写成硬约束。

最短行动闭环 Shortest Action Loop

让一个真实用户，用真实数据，完成一次有价值的动作，并产生可观察的反馈。

切片打分卡 Slice Scorecard

用价值、可行性、证据强度、风险四个维度给候选切片打分，避免凭感觉选第一个。
