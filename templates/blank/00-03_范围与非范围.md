# A00-03 范围与非范围

## 用途 / 何时用

在项目章程阶段、开始访谈和切片之前使用。把“这次做到哪里、明确不做什么、什么情况下需要改范围”写清楚，避免后续把相邻问题不断塞进同一轮验证。

## 填写说明

- “包含”写本轮要覆盖的流程、角色、数据粒度与时间范围。
- “不包含”写相邻但本轮不做的问题、系统和角色；每条说明为什么先不做。
- “边界条件”写范围成立的前提，例如数据可获得、用户在岗、权限已批。
- “依赖”写范围之外但必须到位的人、数据、系统或授权。
- “变更规则”写谁提出、谁批准、什么条件下允许扩大或缩小范围。
- 范围变更后同步更新 A00-01 的版本与日期。

## 字段

### 包含

（逐条列出本轮覆盖的流程、角色、数据粒度和时间范围）

### 不包含

（逐条列出明确不做的内容，并写一句“为什么先不做”）

### 边界条件

（范围成立的前提条件；写成可检查的陈述）

### 依赖

（范围外但必须到位的人、数据、系统、权限；写责任方）

### 变更规则

（提出人、批准人、触发条件、记录位置）

## 质量门自检（G0）

- [ ] “包含”能对应到具体流程、角色和数据粒度。
- [ ] “不包含”至少三条，且每条都有先不做的理由。
- [ ] 业务方已逐条确认“不包含”，不是团队单方面决定。
- [ ] 边界条件可检查，不写“视情况而定”。
- [ ] 每项依赖都有责任方和期望时间。
- [ ] 变更规则写清了提出人、批准人和记录位置。
- [ ] 范围变更后已同步更新项目一页纸的版本。
