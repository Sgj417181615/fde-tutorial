# A04-03 对象模型

> 产物路径：`04_方案设计/04-03_对象模型.md` ｜ 所属阶段：04_方案设计 ｜ 阶段门：G4

## 用途

把业务决策需要的人、事、额度、分配等概念落成对象与关系，作为数据设计、界面设计和写回逻辑的共同语言。对象模型支撑的是决策，不是把源系统表结构照搬一遍。

## 何时用

- 决策清单和 FR 初步成型后；
- 设计界面字段、数据装载或写回逻辑之前；
- 发现同一概念在不同页面叫法不一致时；
- G4 评审时检查数据是否真的支撑得了决策。

## 填写说明

1. 对象名用“中文名 + 英文名”，全表统一，不用同义词。
2. 类型只能填 `core`、`derived`、`use case` 三类。
3. `core` 是源系统里直接有、粒度对得上的对象；`derived` 是算出来的；`use case` 是用户在流程中主动创建或修改的。
4. 关键属性只写决策要用的字段，不抄整张表。
5. 关系写对象之间的业务联系；基数写 `1:1`、`1:N` 或 `N:1`，并说明方向。
6. 来源写系统、表、人工记录或规则计算。
7. 负责人写维护该对象的角色；未定的标“待确认”，不要空着。

## 质量门自检（G4）

- [ ] 每个对象只出现一次，名称与业务术语表一致。
- [ ] 类型只使用 `core`、`derived`、`use case`，没有第四种。
- [ ] `core` 对象能在源系统中找到，且粒度与决策一致。
- [ ] `derived` 对象写明由哪条规则或计算产生。
- [ ] `use case` 对象写明用户在哪个动作中创建或修改。
- [ ] 关系与基数能支撑决策清单和 FR，不是装饰性画图。
- [ ] 每个对象都有来源与负责人；负责人待定的已明确标注。
