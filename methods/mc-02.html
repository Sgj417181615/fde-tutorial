最短行动闭环

一个切片怎么切，才算“最短”而不是“最小功能包”？

本页要回答一个切片怎么切，才算“最短”而不是“最小功能包”？

读完你能

  • 判断这个方法是否适用于你的场景；
  • 按步骤执行并产出关联 artifact；
  • 用检查清单自检，避开反模式。

前置

无前置，从本页开始。

一句话回答

以“一次真实用户动作”为单位，把输入 → 判断 → 动作 → 反馈四段连起来；四段都能被观察到，才算一个最短闭环。闭环外的东西一律先删。最短不是功能最少，而是从拿到输入到看见结果之间，路径最短、参与角色最少。

最短行动闭环 用来判断边界，不用来评价功能多不多。

什么时候用

用：

  • 手里有两三个候选切片，需要判断哪一条能独立走通；
  • 范围开始膨胀，有人往里面加报表、通知、移动端；
  • 写 Demo 脚本前，需要确认演示有没有“最后一步”。

不用：

  • 证据还不足以说清用户、时点或输入。先回现场；
  • 反馈只能靠口头说“挺好的”，系统里看不到变化。先把反馈做成可见的；
  • 上游切片还没稳定，却想先做下游。先补依赖，不要硬连。

怎么做

  1. 写角色和时点：只写一个人、一个具体时点，例如“陈静在每月 25 日前”。
  2. 写输入：列出这次判断真正要用的数据，并注明来源；拿不到的数据不要写成必需。
  3. 只留一个判断：写出一个最终决策。出现第二个“决定”，就把它移到闭环外或下一轮。
  4. 写动作：写清用户在哪个界面、点什么、保存后发生什么，不要写“系统自动处理”。
  5. 写反馈：必须是可观察的结果，例如状态变了、额度变了、重新打开还能看到。
  6. 删闭环外：报表、通知、权限管理、移动端，凡是不影响这一次判断与动作的，先删。
  7. 空手走一遍：让用户本人操作，你不碰鼠标；卡住的地方就是闭环缺口。

排班案例片段

案例 CB-03 里，DC-1“各亚专科额度怎么分”和 DC-2“某个人分到哪个亚专科”被合并成一次额度分配方案的确认。DC-3 是发现缺口时的中间决策，DC-4 是审批动作，教程不把它们全部承诺进五天 Demo。

这条边界让闭环保持最短：陈静拿到需求、额度、可用天数，做出一次分配，保存后看到冲突与剩余额度变化【示例】。S2 个人排班与换班依赖这次分配的结果，所以放到第二轮。CB-04 的“不做什么”也明确排除了 S2、S3、工资绩效和自动替人做最终决定。

检查清单

  • [ ] 只有一个用户、一个时点、一个最终决策。
  • [ ] 输入、判断、动作、反馈四段齐全，没有跳步。
  • [ ] 反馈可观察，且能再次打开核对。
  • [ ] 用的是真实数据，不是为了演示拼的玩具数据。
  • [ ] 边界写进了“不做什么”，不是留在脑子里。
  • [ ] 用户不靠你提示也能走完。

反模式

  • 把功能清单当闭环：功能再多，没有“判断—动作—反馈”就只是菜单。
  • 闭环里塞两个以上决策：演示一定会超时，责任也说不清。
  • 把“页面好看”当反馈：反馈要能改变下一步，不是一句评价。
  • 上游未就绪先做下游切片：S2 依赖 S1 的分配结果，顺序反了会被数据卡住。
  • 把审批签字当反馈：签字是动作，反馈应是状态或数据真的变了。
