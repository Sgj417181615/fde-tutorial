工具链与硬编码路径

转写、Word、HTML 验收三条工具链怎么用，哪些参数绑定旧项目、换项目先改哪里。

本页要回答现有工具链哪些能直接用，哪些一带到新项目就会出错？

读完你能

  • 跑通转写 → 术语校正 → Word/HTML 的最小链路；
  • 找出脚本里的硬编码路径与项目参数；
  • 写出一份换项目前的改造清单。

前置

先读：记录：把现场变成证据

何时用
新项目第一次跑转写、Word 或 HTML 验收之前
输入
已授权的录音/音频、A02-03 术语与说话人表、可运行的工具目录
输出
为 A02-02 逐字稿提供原始转写稿（定稿与说话人标注在 work-03 完成）、工具链检查记录（无 artifact ID），三条链路各一条可复现命令
验收与耗时
换项目后可重复运行；约 3 小时

工具在旧项目里跑得很好。换到新项目，第一条命令就报“找不到文件”，可文件明明在那儿。你改了输入路径，输出又写回旧项目；截图看起来成功，打开却是 Chrome 的目录列表。

脚本没坏，是它绑死在旧项目上。路径、项目名、输出目录、浏览器位置，任何一项写死，换项目就会静默出错。

何时用

该用：

  • 新项目启动，第一次跑转写、Word 生成或 HTML 验收之前；
  • 从别的项目复制了工具目录，准备直接复用；
  • 工具报“找不到文件”“输出为空”，但源文件确实存在。

不该用：

  • 只做一次的手工任务。为一次性操作搭管线，成本高于手工；
  • 录音尚未获得授权、材料未脱敏时。先解决权限，再谈工具；
  • 把工具链当成交付物。它是开发期工具；它喂给 A02-02、A02-03 和最终文档，本身不进档案。

工具包给的是可执行起点，不是即插即用的交付物 [S16]。复制后先检查参数，不要直接运行。

停一下：你怎么判断一条命令“真的成功了”？

不是看终端没报错，而是看三件事：输出文件存在、内容能打开、写入位置在新项目内。少一件，都是“看起来成功”。

前置与输入

输入 用来做什么 缺失时
录音/音频（已获授权） 转写，产出 A02-02 先补 A00-04，不要用未授权的录音
A02-03 术语与说话人表 把错词改对，统一业务词 先建表，否则错词带进文档
工具目录 提供转写、Word、HTML 验收脚本 从团队工具包复制，并确认运行时齐全

先确认命令真的存在：

python --version
ffmpeg -version
pandoc --version

Chrome 不一定在 PATH 里。Windows 常见位置是 C:/Program Files/Google/Chrome/Application/chrome.exe，macOS 在应用包内。找不到就用 CHROME 环境变量指定。

八步操作

第 1 步：复制工具并冻结版本（10 分钟）

把工具目录复制到新项目根目录下，不要从旧项目路径直接运行。记下 Python、ffmpeg、pandoc、Chrome 的版本。venv/ 和 models/ 不要跨项目共用。

第 2 步：跑通转写最小链路（25 分钟）

先把音频转成 16k 单声道 wav，再转写。以团队 _asr/ 为例：

ffmpeg -i 录音/第一段.m4a -ar 16000 -ac 1 -c:a pcm_s16le _asr/wav/第一段.wav
_asr/venv/Scripts/python.exe _asr/asr.py run --seg 第一段 --slice 180
_asr/venv/Scripts/python.exe _asr/asr.py run --seg 第一段
_asr/venv/Scripts/python.exe _asr/asr.py align
_asr/venv/Scripts/python.exe _asr/asr.py export

先跑 180 秒验管线，再跑全段。align 不能省，否则各段说话人编号互不相干。热词表只放已核实的词，否则等于让引擎替你“确认”。

产出写到 A02-02，字段至少有时间戳、说话人、原文、置信度、备注。

第 3 步：校正术语（15 分钟）

拿 A02-03 对照逐字稿，改同音词、业务缩写、人名。只改词，不改语气和停顿；改完在备注写“已按术语表校正”，保留原稿。

第 4 步：生成 Word 并验收（20 分钟）

pandoc 03_方案.md -f markdown -t docx \
  --reference-doc=reference.docx --toc -o 03_方案.docx
python 工具/docx-pipeline/verify_docx.py 03_方案.md 03_方案.docx

verify_docx.py 把源 Markdown 的正文逐行拿到 docx 里找，找不到就报“内容丢失”。pandoc 会吞紧跟段落、中间没有空行的列表。验收看三样：正文行齐全、表格数量对得上、目录能更新。

第 5 步：跑 HTML 验收（20 分钟）

用无头 Chrome 截图并导出渲染后的 DOM：

CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"
"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=5000 --window-size=1680,1150 \
  --screenshot="D:/qa/index.png" "file:///D:/qa/index.html"
"$CHROME" --headless=new --disable-gpu --dump-dom \
  "file:///D:/qa/index.html" > "D:/qa/index.dom.html"

验收三点：截图不是空白、DOM 开头是 <!DOCTYPE html>、关键数字能在 DOM 里搜到。两个坑：输出路径用纯 ASCII 绝对路径；URL 不能多空格，否则 Chrome 会把字符串当目录，截出目录列表还照样存成 .html。

第 6 步：找出硬编码（25 分钟）

先搜绝对路径和旧项目名：

rg -n "[A-Za-z]:[\\/]|/Users/|/home/|file:///|localhost" \
  --glob "*.py" --glob "*.sh" --glob "*.js" --glob "*.ps1" .
rg -n "^\s*(ROOT|BASE|OUT|SRC|DATA|CHROME|PAGES|BUILD)\s*=" \
  --glob "*.py" --glob "*.sh" .

第二条搜配置常量：很多脚本把 ROOT、OUT、PAGES 写死在文件顶部。最后搜旧项目名、旧客户名和注释里的旧目录。命中分四类：

类型 例子 处理
项目绑定 d:/旧项目/_build 必须改成从脚本位置推导
机器绑定 Chrome、Python 安装路径 用环境变量或参数，给默认值
相对路径 _asr/wav 可以保留，但必须相对项目根
密钥 API Key、口令 移到 .env，不提交

第 7 步：改成一个入口（20 分钟）

Python 用脚本位置推导根目录：

from pathlib import Path
ROOT = Path(__file__).resolve().parents[1]
OUT = ROOT / "out"

Shell 同理：

HERE="$(cd "$(dirname "$0")" && pwd)"
ROOT="$(dirname "$HERE")"
OUT="${OUT:-$ROOT/out}"

原则三条：一个地方配置根目录；能推导就不要记；机器相关的值走环境变量。

第 8 步：换项目验证（25 分钟）

把项目复制到带中文和空格的目录，如 D:/qa/换项目 测试/。然后：

  1. 从别的工作目录运行：cd /tmp && python "D:/qa/换项目 测试/工具/export.py" --input ...；
  2. 确认输出只落在新项目目录，旧项目没被写入；
  3. 再跑第 6 步的搜索，旧路径命中应为 0；
  4. 重跑 Word 和 HTML 验收，正文、表格、关键数字都在。

脚本从 __file__ 推导根目录，换工作目录也能跑；如果仍依赖“当前目录”，这一步就会失败。失败说明你找到了最后一个绑死点。

输出与验收

转写链路产出的是 A02-02 的原始转写稿（02_现场记录/02-02_逐字稿/），说话人校正与术语统一在 work-03 完成后才算定稿；检查记录本身没有 artifact ID，放在 00_项目章程/工具链检查记录.md。

记录覆盖三条链路的入口命令、输入、输出、写死的值、改法和验证结果。

工具链本身不设独立阶段门；它服务的 A02-02 逐字稿、A02-03 术语与说话人表，在 G2 现场记录门被检查。工具跑通只说明文件生成了，产物是否过关仍看“每句能否回到录音时间点、每个术语是否有说话人确认”。

通过标准：

  • 三条链路各跑通一次，命令可复制；
  • 旧路径命中为 0，从另一个工作目录运行仍成功；
  • 输出只写在新项目内，记录每行有结果和负责人。

不通过时：不要删掉报错继续跑。把失败命令、报错和当前目录写进记录，再修路径。

模板：检查记录怎么填

工具链检查记录 无 artifact ID，可直接复制
检查项 命令或位置 期望 实际 结论 负责人
转写 asr.py run + align 生成 raw.json 与 speakers.json
Word verify_docx.py 无内容丢失
HTML 截图 + dump-dom 非空、有 DOCTYPE
硬编码 rg 两条命令 0 命中

填写说明：一行一个可观察结果；“实际”栏贴关键输出，不写“正常”。

排班案例：换项目时先改哪里

排班项目里，这一页接在 work-03 之后：录音进 A02-02，术语表进 A02-03。假设你从上一个医院项目复制了 _asr/，直接跑 asr.py list，显示“0 段待转写”。

先别怀疑录音。看脚本顶部的输入目录是不是还指着旧项目。把 ROOT 改成从 __file__ 推导，默认输入改成 ROOT / "录音"，再跑 list，应该能看到“第一段”。

Word 和 HTML 同理。docx 少一行，先跑 verify_docx.py；HTML 截图只有目录列表，先查 URL 有没有空格。这一页只改参数，不改证据内容。

常见失败

现象 原因 处理
报“找不到文件”，文件确实存在 路径写死到旧项目 搜绝对路径，改成项目根推导
输出跑到旧项目 输出目录是常量 改成 ROOT / "out"，查写入位置
截图成功，打开是目录列表 URL 多了空格 检查引号，确认 URL 以 .html 结尾
Word 少了一段 pandoc 吞了列表 列表前补空行，跑校验脚本
换机器后 Chrome 找不到 浏览器路径写死 用 CHROME 环境变量
跨段说话人编号对不上 没跑 align 转完后补跑 align

动手 20 分钟：做一次工具链审计。

  1. 在你的项目根目录跑第 6 步的两条 rg 命令；
  2. 挑出 3 条命中，按“项目绑定 / 机器绑定 / 相对路径 / 密钥”分类；
  3. 改掉其中 1 条项目绑定路径，从另一个工作目录重跑；
  4. 把命令、实际输出和结论写进检查记录。

自检：旧路径搜索为 0；从 /tmp 运行仍成功；输出没有写回旧项目。

自检清单

  • [ ] 工具目录已复制到新项目根，没有从旧路径运行；
  • [ ] 转写先试跑 180 秒再跑全段，且跑过 align；
  • [ ] 术语校正只改词，不改语气；
  • [ ] Word 验收检查了正文行、表格数量和目录；
  • [ ] HTML 验收看了截图、DOM 开头和关键数字；
  • [ ] 两条 rg 覆盖绝对路径与常量，旧路径命中为 0；
  • [ ] 从另一工作目录能跑通，输出只在新项目内；
  • [ ] 检查记录每行有实际结果和负责人。

三问自测

1. 为什么“终端没报错”不等于工具跑成功？ 很多失败是静默的：输出写到旧目录、Chrome 存下目录列表、pandoc 吞了一段。必须查文件存在、内容可读、位置正确。
2. 为什么根目录要从脚本位置推导，而不是靠当前目录？ 当前目录由调用者决定，从别处运行时相对路径会指错。`__file__` 指向脚本自身，推导出的根目录才稳。
3. 哪些路径可以保留，哪些必须改？ 相对项目根的可以保留；项目绑定的必须改；机器绑定的走环境变量；密钥移到 `.env`。

本章带走

  1. 三条链路都要“文件存在、内容可读、写对位置”才算成功。
  2. 硬编码审计先搜绝对路径和配置常量，再按四类处理。
  3. 改完必须换目录、换工作目录重跑；旧路径命中为 0 才算解绑。
