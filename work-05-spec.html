一小时压出评审包

把 one-pager、FR、对象模型、生命周期、界面、MVP 范围和 KPI 拼成可评审包。

本页要回答怎样在一小时内凑齐一份能被业务和技术同时评审的材料？

读完你能

  • 按顺序拼出八件套并检查互相一致；
  • 用控制矩阵标出人机分工；
  • 写出 MVP 范围与非范围。

前置

先读：从证据到模型

何时用
D1 收口或 D2 方案设计结束、G4 评审之前
前置
切片已选定，A03-01～04 可互相追溯，规则有确认人
输入
As-is、决策清单、规则库、one-pager 草稿、证据台账
输出
A03-05 one-pager、A04-01～06、A05-05 KPI 基线与验证标准
阶段门与耗时
G4 方案设计门；装配约 60 分钟，评审前检查 10 分钟

16:10，17:00 评审。one-pager 是上周的，FR 是昨天的，对象模型画了一半。业务方看 one-pager，技术方看 FR，放一起却打架——封面写“不自动替人做决定”，FR-02 写“系统自动分配”；对象模型里没有“冲突”，界面上却要显示冲突面板。

材料不少，是没装配成评审包（Spec Package）：围绕同一决策、同一版本、能互相对上的一组产物。评审者要在半小时内判断“做不做、做到哪、还缺什么”。本页给装配顺序、交叉检查和评审前检查。

何时用

该用：

  • D1 收口，把现状、切片和 one-pager 交给业务方确认；
  • D2 结束，让业务和技术同场评审 FR、对象、生命周期和范围；
  • 进 Demo 前，冻结一版可追溯基线。

不该用：

  • 切片没选定。先回 从证据到模型 做 A03-03；
  • 只有一位评审人、只问一个问题。发一页 one-pager 就够；
  • 只想汇报进度，不准备接受修改。

停一下：把包内文件摊开，你能指出哪份是主文件、其余几份分别验证它的什么吗？指不出来，它们只是同一文件夹里的八份文档，还不是评审包。

前置

前置 判断标准 没做到会怎样
切片已选定 A03-03 只有一个“选中”，A03-05 草稿六段都有内容 重新吵“做哪个”，版本对不上
现状可追溯 A03-01、A03-02 的判断有证据 ID FR 被质疑“凭什么”
规则已分层 硬约束有确认人，优化目标没混层 该拦的只提示
评审角色已定 业务、技术、数据权限人各至少一位 只剩“总体不错”

最常见的失败，是装配时不断加“这个也得写”，最后交出没人读完的材料。

输入

输入 取什么 用在哪
A03-01、A03-02、A03-05 角色、判断、决策、封面六段 封面、FR 场景、决策清单
A03-03、A03-04 选中切片、规则分层 固定边界、FR 校验、控制矩阵
A02-04 证据台账 证据 ID、状态、权威性 给 FR 挂依据
A03-06～A03-08（走了 Day1 路线时） D1 工作底稿、阶段门记录、D2 输入清单 直接作为评审包的现状与未决项来源

不要在这 60 分钟里重新访谈或重选切片。输入不够就标“待确认”，写清负责人和截止日期。

一小时的装配顺序

顺序不能反：先定边界，再放封面，再逐层向下展开。先写对象模型再补 one-pager，通常会把范围撑大。

第 1 步：定包内清单与版本（5 分钟）

在文件夹根部放 00_评审包索引.md，列八件产物、版本、切片、月份和三个评审问题。八件是：A03-05 one-pager、A04-01 决策清单、A04-02 FR、A04-03 对象模型、A04-04 生命周期、A04-05 界面、A04-06 MVP 范围、A05-05 KPI。

00_评审包索引.md 是工作文件，不属于 42 个 artifact，不占档案编号；它只服务于这一次评审，评审结束后可以归档或删除。

纪律：同切片、同月份、同版本号；旧稿移入 _archive/；索引写三个“必须今天决定”的问题，例如决策选对没有、硬约束是否阻断、MVP 砍得是否合理。

八件和索引不用自己拼，可以整包拿走：

8 份八件评审包one-pager、决策清单、FR、对象模型、生命周期、界面、MVP 与 KPI，外加索引。fde-review-pack.zip

全部为离线 zip：解压即用，不联网、不需要安装。模板是 Markdown 文件，用任意文本编辑器或 Obsidian 打开。工具包下载在 Day1 总览。

第 2 步：把 one-pager 放成封面（8 分钟）

A03-05 是评审者最先读、也可能只读的一页。按 案例 CB-04 检查六段：用户、决策、输入、动作、价值、不做什么。

判断只有一条：读完这页，评审者能说出“谁在什么时候做一个什么决定，这次不做什么”。说不出来，先改封面。CB-04 明确排除个人排班（S2）、住院总轮转（S3）和自动替人决定，后面的 FR 才有围栏。

第 3 步：对齐决策清单并写 FR（14 分钟）

先把 A03-02 的决策搬进 A04-01，补决策人、时点、输入、动作、频率、影响对象；只留本次切片，区分最终、中间和审批动作。

再写 FR：谁，在哪个界面，依据什么输入，判断什么条件，做什么决定，通过什么动作写回，验收看到什么。 一条只装一个决定。

案例 CB-07 可对照：FR-02 王芳可用 9 天、填 10 天被阻止并说明超出 1 天【示例】；FR-05 批准后状态变为已发布、额度与剩余同步变化。每条 FR 指回一行决策和一条证据。

第 4 步：搭对象模型与生命周期（12 分钟）

把 FR 里的名词圈出来。core = 源系统直接有；derived = 需要算出来；use case = 用户创建或修改。

案例 CB-05 的分法：人员、亚专科、班型、额度是 core；分配、调整记录是 use case；冲突是 derived。每个对象补属性、关系、基数、来源、负责人。检查：每个名词有对象；每个对象至少被一条 FR 使用。

再画生命周期。案例 CB-06 的分配对象走“建议 → 已确认 → 已发布 → 调整中 → 已归档”，每个 Action 写迁移后状态、写回字段、权限、校验。判断标准：关掉再打开，变化还在。 只弹提示不算写回；批准至少改 Allocation.status 并同步 Quota.used。

第 5 步：补界面与人机控制矩阵（8 分钟）

A04-05 放支撑决策的计算和提示：剩余额度、缺口、冲突严重度、建议动作。每项写类型、输入、来源、输出、界面区域、交互、失败处理。数据缺失显示什么？冲突算不出时阻断还是提示？

人机控制矩阵 把每步分成完全自主、人在回路、纯人工，并写清验证者、审批者和回滚方式。排班案例：冲突检测完全自主；额度分配人在回路，陈静决定、系统校验；最终审批纯人工。

三条纪律：每步只选一个级别；人在回路必须有验证者，完全自主必须有回滚；纯人工也要留记录。“系统自动分配”要么降成建议，要么补规则、确认人和回滚。

第 6 步：收 MVP 范围与 KPI（7 分钟）

A04-06 写五栏：包含、不包含、待确认、演示必需、可延后。案例 CB-09 的边界：一个月、三个亚专科、四个人的脱敏数据；额度全景、分配到人、C1/C2 识别、组长确认、主任审批、写回可重开。不做自动优化算法、工资绩效和移动端。

A05-05 至少写指标、基线、目标、测量方式、反指标。案例 CB-08 的“约 3 小时”是回忆值，必须保留“约”并注明复测；没有实测，不能对外说“下降 X%”。

交叉检查：对不上就退回

装配完不要从头读，按四条连线检查。连不上就退回对应产物，不要在会上口头解释。

检查 连什么 对不上时
范围一致 封面“不做什么” ↔ FR 列表 ↔ MVP 演示必需 删越界 FR，或砍范围
决策可追溯 每条 FR ↔ A04-01 的一行决策 补决策，或删 FR
对象有写回 FR 名词 ↔ 对象；FR 动作 ↔ 状态与字段 补对象、补写回
规则与权限 硬约束 ↔ 阻断；Action ↔ 操作者、审批者 改校验，或补角色

最常断的是“对象有写回”。生命周期图很漂亮，却没有写回字段；建设时才发现最后一步存不下来。

评审前 10 分钟

按顺序做完五项，不要临场发挥：

  1. 从文件夹根部打开索引，确认八份文件都在；
  2. 用 60 秒读封面，说得出一个决策和三条“不做什么”；
  3. 核对切片名、月份、版本号，以及额度、缺口、可用天数三个数字和三个人名；
  4. 检查每个“待确认”都有负责人和截止日期；
  5. 走一遍演示主路径，确认五步内没有死路；断网打开一次，写下三个评审问题。

第 3 项最伤信任：同一个额度在两张表里差 2 人天，业务方会怀疑整包材料。

输出

输出（路径） 最小内容
A03-05 one-pager 03_现状与切片/03-05_use-case-one-pager.md 六段齐全，明确不做什么
A04-01 决策清单 04_方案设计/04-01_决策清单.md 一行一决策，有决策人和时点
A04-02 FR 04_方案设计/04-02_功能需求FR.md 固定句、验收、证据 ID
A04-03 对象模型 04_方案设计/04-03_对象模型.md core/derived/use case 齐全
A04-04 生命周期 04_方案设计/04-04_生命周期与写回.md 状态、Action、写回、权限
A04-05 增强与界面 04_方案设计/04-05_增强与界面.md 计算、区域、失败处理
A04-06 MVP 范围 04_方案设计/04-06_MVP范围与非范围.md 包含、不包含、待确认、演示必需、可延后
A05-05 KPI 05_五天验证/05-05_KPI基线与验证标准.md 基线、目标、测量、反指标

阶段门

G4 通过：六件方案产物与 KPI 同切片、同版本；每条 FR 追到决策、对象、写回和证据；对象三类齐全；生命周期有写回；控制矩阵每步有级别、验证者和回滚；MVP 有非范围。KPI 这一轮只要起草到“有基线口径”，它的门在 G5。

有条件通过：只缺一项非关键数据或权限，已标“待确认”，有负责人和日期，不在演示主路径上。

不通过：FR 是功能清单；生命周期没有写回；控制矩阵缺步骤或把“自动”当默认；MVP 含未验证算法；方案承诺降幅却拿不出基线指标。

模板

控制矩阵最容易漏，先用这张骨架。其余模板在 templates/blank/ 下按编号对应。

A04-05 配套：人机控制矩阵 可直接复制
步骤 自主级别 系统动作 验证者 审批者 回滚方式
冲突检测 完全自主 计算超排、缺口 陈静抽查 无 回退人工核对
额度分配 人在回路 校验可用天数与额度 陈静 周主任 恢复上一版

填写说明：级别三选一；人在回路写验证者；完全自主写回滚；纯人工留记录。没有验证者或回滚的“自动”，不算控制。

控制矩阵还要能审计：每个动作记录操作人、时间、改前/改后值、依据的规则版本。没有审计字段的“人在回路”，事后回答不了“是谁批准了这次例外”。审计字段可以落在界面事件日志里，不必都加进矩阵本身，但必须在 A04-05 里写明存放在哪。

排班案例

评审时，每份文件只看最关键的一句：

产物 案例片段 看哪一句
A03-05 案例 CB-04 只承诺额度分配一个决策，不做 S2、S3 和自动替人决定
A04-02 案例 CB-07 王芳可用 9 天，填 10 天时保存被阻止并说明超出 1 天【示例】
A04-03、A04-04 案例 CB-05 案例 CB-06 冲突是 derived 对象；批准后 Allocation.status 和 Quota.used 真的变化
A04-06、A05-05 案例 CB-09 案例 CB-08 不做自动优化算法；约 3 小时是回忆值，必须复测

这张表也是交叉检查的缩影：one-pager 约束 FR，FR 落到对象和生命周期，MVP 决定哪些进演示，KPI 决定演示时测什么。

常见失败

现象 原因 处理
封面写“不自动决定”，FR 写“自动分配” 两份材料分开写 以封面为准，自动降为建议，或补规则与审批
FR 每条都以“系统应该支持”开头 功能清单当需求 用固定句重写，补角色、判断、写回和验收
对象不全，生命周期没有写回 只建已有表，状态图当流程说明 补 derived/use case 对象和写回字段
MVP 全量演示，KPI 没基线 把“真实”当“全量”，把愿望当指标 收到一个月、三个亚专科、四个人

动手 20 分钟：拿现有材料做最小装配。

  1. 列出包内文件，写版本号和切片；
  2. 抽三条 FR，连线到决策、对象、写回，标“通”“断”“缺”；
  3. 把“断”和“缺”改成具体动作：补哪份、找谁、何时补。

自检：三条 FR 都能指到决策；至少一个动作落到写回字段；缺口都有人名和日期。

三问自测

1. 为什么先放 one-pager，而不是先写 FR？ one-pager 先固定边界：一个决策、一个用户、一组“不做什么”。边界定了，FR 才知道写什么；先写 FR 容易越写越多。
2. 生命周期图为什么必须有写回字段？ 状态图说明“可以怎么变”，写回字段说明“变了之后存在哪里”。没有写回，关掉页面就恢复原状，无法证明决策真的发生。
3. 人机控制矩阵主要防什么？ 防“自动”成为没人负责的默认选项。写不出级别、验证者、审批者和回滚方式，就说明这一步还不该自动化。

自检清单

  • [ ] 八件产物同切片、同月份、同版本号；
  • [ ] one-pager 只承诺一个最终决策，写明不做什么；
  • [ ] 每条 FR 追到决策、对象、写回和证据；
  • [ ] 对象覆盖三类，每个 Action 有状态迁移和写回；
  • [ ] 控制矩阵每步有级别、验证者、审批者、回滚；
  • [ ] MVP 包含／不包含／待确认写满，演示项可走通；
  • [ ] KPI 有基线、目标、测量、来源和反指标。

本章带走

  1. 评审包是同一决策、同一版本、能互相对上的产物组，不是八份文档。
  2. 装配先边界后细节：索引、封面、决策与 FR、对象与生命周期、界面与控制矩阵、MVP 与 KPI。
  3. 评审前用交叉检查找断点，再用 10 分钟查版本、数字、角色和演示路径。
